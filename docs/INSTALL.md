# Установка

## Требования

Целевая платформа: rooted LG webOS на ARMv7 с Luna API, jailer, Node.js, Python 2 и установленным CBE-движком браузера LG. Для сборки пакетов нужен webOS CLI; версии источников и runtime закреплены в [inventory/upstreams.json](../inventory/upstreams.json) и package metadata. Совместимость native-компонентов зависит от ABI и browser image конкретной версии webOS.

Подготовьте SSH по ключу и работающий Homebrew Channel. Доступ к отладке предоставляйте только в доверенной сети. Каталоги root-runtime должны принадлежать root и не разрешать запись другим пользователям; это относится ко всей цепочке родителей. Сохраните заменяемые файлы перед установкой.

## Пакеты и карта размещения

Источники базовых пакетов и native prerequisites: [packages/README.md](../packages/README.md). Точные целевые пути и права содержатся в [inventory/deploy-map.json](../inventory/deploy-map.json). Посмотреть их для компонента:

```sh
python3 tools/deployment_plan.py --component hearth
```

Сначала устанавливаются и регистрируются пакеты приложений, затем overlays и private runtime. Копирование файлов не заменяет регистрацию приложения/сервиса в SAM. Root hooks подключаются последними, после разового запуска компонентов. Инструмент вывода карты не устанавливает файлы автоматически.

## Hearth

Установите базовый Hearth, затем разместите overlay по карте. Файлы `components/vpn/hearth-ui` устанавливаются в `custom-vpn` внутри Hearth. Forecast helper и CA bundle из `components/hearth/service` размещаются рядом с audio runtime; cache создаётся отдельно и остаётся локальным.

Настройки главного экрана описаны в [CONFIGURATION.md](CONFIGURATION.md). При первом запуске выберите город для погоды; существующие предпочтения при обновлении сохраняются.

## Kick

Упакуйте `components/kick/source/app` вместе с `service` и установите основной пакет. Отдельно упакуйте и зарегистрируйте `native-player` как `com.jakubjirak.player`, предварительно добавив локальный LG executable согласно prerequisites.

Для ускоренного плеера нужен private mirror: `source/app` → `applications/com.jakubjirak`, `source/service` → `services/com.jakubjirak.service` относительно каталога helper, указанного в карте. Он содержит **обе** части: HTTP helper ищет ресурсы приложения относительно service. Каталоги helper — root-owned, 0700, файлы — по карте.

`installed-app` и `installed-service` содержат готовые варианты ресурсов для установленного приложения. Карта различает эти пути и исходники private mirror. Папка сессий `.browser-runtime` создаётся service и не переносится между устройствами.

## VK ×2

Зарегистрируйте пакет `launcher`+`service` и отдельный пакет `native` с локальным LG executable. Разместите `runtime` по карте. Сначала запустите observer вручную и проверьте переход VK→Home→VK×2; затем подключите его hook. Снимки потока создаются в root-only временном каталоге.

## VPN

1. Выберите поддерживаемый адаптер по [ADAPTERS.md](../components/vpn/ADAPTERS.md) и подготовьте его бинарники/профиль.
2. Создайте root-owned каталог runtime с подкаталогами `bin`, `state`, `logs`, все —0700. Целевой каталог указан в карте; существующий путь сохраняется для совместимости с установленным состоянием.
3. Установите `root` целиком, включая `providers`: один manager.js без адаптера работать не будет. Примените права карты.
4. Создайте локальный config.json из примера: укажите `provider` и его `providerConfig`, оставьте enabled=false. Config, клиентское состояние и control socket —0600.
5. Запустите controller, выполните необходимую настройку/вход и проверьте включение и возврат обычного подключения. После этого подключите startup hook.

При обновлении существующего runtime сначала отключите соединение и дождитесь возврата обычной сети, затем остановите manager, замените комплект файлов и запустите его заново. Новая версия читает прежнюю плоскую конфигурацию без переноса аккаунта.

UI и control.js используют общий протокол; смена движка не требует менять их. Переход между разными клиентами выполняется только после подтверждённого отключения предыдущего.

## Home, аудио и автозапуск

Устанавливайте `components/system` последним. В настройках Hearth откройте Options и включите **Set Hearth as the TV’s Home app**. Эта настройка записывает `general.defaultApps.home`, сохраняет предыдущий Home и создаёт guard для возврата при удалении Hearth; сам `guard.sh` не назначает Home. Guard хранится в root-private `/var/lib/webosbrew/hearth-homeapp`, каталог и скрипт —0700, previous —0600; вся цепочка родителей должна принадлежать root и не допускать group/world write. Overlay сохраняет эти права при повторном включении настройки. Включение ТВ остаётся штатным, без принудительного запуска приложения LiveTV через boot override.

После установки проверьте обычное включение, Home, возврат в ТВ и аудио-переход. Не меняйте общие picture/audio settings для подключения компонентов. Для удаления компонента сначала отключите только его hook и остановите собственный runtime, затем верните сохранённые файлы.

## Доступ и обновление

Используйте собственные SSH-ключи, `authorized_keys` —0600, `.ssh` —0700. Hook `30-sshd-key-only` отключает парольный вход; дополнительные домашние устройства получают доступ своими ключами. Не включайте параллельно парольный SSH или Telnet. Hook `29-local-debug-only` предназначен для изоляции TCP 9998 в IPv4/IPv6 без изменения остальных правил. Для него нужны рабочие kernel tables, а не только установленные iptables/ip6tables. Результат установки правил записывается в root-private `home-kit/inspector-isolation.json`; проверьте его и отдельное подключение из LAN. Если kernel tables отсутствуют, hook не обеспечивает защиту: сначала требуется отдельное совместимое решение ограничения отладчика. Для изолированного отладчика используйте SSH local forwarding. Штатный аварийный механизм Homebrew не заменяется этими hooks.

Перед обновлением сохраните собственный откат вне исходников, отключите подключение, дождитесь `quiescent=true` и остановите controller. `tools/device_sync.py` сравнивает карту с устройством; `--apply` атомарно заменяет только отличающиеся управляемые файлы и записывает идентификатор manifest. Скрипт не обновляет localStorage, конфигурацию или авторизацию клиента и не перезапускает службы:

```sh
python3 tools/device_sync.py --host TV_HOST --identity /path/to/key --known-hosts /path/to/known_hosts
# После подготовки отката и остановки изменяемых служб добавьте --apply.
```

После замены запустите controller и откройте Hearth заново. При обновлении со старого размещения Home-guard перенесите `previous` в защищённый каталог, замените startup-ссылку и только затем удалите прежние guard.sh/previous. Другие файлы старого каталога не удаляйте. Вывод повторного сравнения должен содержать пустой `changes`; локальные секреты и ресурсы prerequisites намеренно находятся вне этой сверки.
