# Адаптеры VPN

## Граница расширения

Hearth→control.js→manager.js используют один протокол: status/on/off/login/providers/select. Manager выбирает реализацию по `provider` из явного реестра `root/providers/index.js`; произвольные пути модулей и shell-команды в конфигурации не поддерживаются.

Адаптер экспортирует `id`, `label`, `capabilities`, `available(root, settings)`, `create(context)` и, для браузерного входа, `validateAuthURL(url)`. Capabilities не зависят от состояния аккаунта; `browserLogin` означает поддержку интерактивного входа, а не обязательность Google или определённого сервиса.

| Метод | Ответственность |
|---|---|
| `start()` | Запустить/подхватить собственный клиент и наблюдение за ним |
| `request(action)` | Применить on/off/login без принятия URL, команд или путей от UI |
| `status(includeLogin)` | Вернуть нормализованное состояние; URL входа — только при явном запросе |
| `close()` | Остановить наблюдение; отключённый клиент освободить, работающий не обрывать при перезапуске manager |

Context содержит `root`, `settings` (из providerConfig), начальное `enabled`/`failure` и callback `onFailure(code)`. Адаптер самостоятельно управляет процессами клиента, DNS/маршрутами, проверкой доступности и восстановлением исходного подключения. При отказе он возвращает сеть в исходное состояние и вызывает onFailure, чтобы controller сбросил желаемое включение.

`status` возвращает `state`, `connected`, `authenticated`, `loginReady`, `busy`, `quiescent` и необязательные `clientVersion`, `hostname`, `endpoint`, `dnsMode`, `lanAllowed`, `error`. Manager фильтрует поля перед передачей в UI. Приватные ключи, cookies, полный client status и stderr никогда не возвращаются. Auth URL дополнительно проверяется политикой конкретного адаптера.

Состояния: starting, connecting, on, disconnecting, off, off-login, login, approval, endpoint-offline, failed, error, setup. `connected=true` допустимо только после проверки фактического соединения, а не при наличии процесса. `quiescent=true` означает, что клиент отключён и его сетевые изменения восстановлены: после этого разрешена смена реализации. Секреты клиента остаются в его root-private state, не в общем status.

## Текущий адаптер: Tailscale

Реализация: `root/providers/tailscale.js`. Официальный ARM-архив и SHA256 закреплены в `packages/tailscale-provenance.json`. Из верхнего каталога архива установите два файла непосредственно в `bin/tailscale` и `bin/tailscaled`.

`providerConfig` содержит hostname, exitNodeIP, exitNodeName, acceptDNS=false и dnsMode. Используется существующий выходной узел tailnet; системный DNS и доступ в LAN сохраняются. Адаптер проверяет online/handshake/приём данных, маршрут и HTTP-доступность. Неудачное соединение автоматически отключается с восстановлением сети. Routing helper сохраняет исходный rp_filter и восстанавливает его при off. Интерактивный вход поддерживает только разрешённые HTTPS-адреса сервиса.

## Добавление другого движка

1. Реализовать модуль контракта и включить его в явный реестр. Проверить бинарник на ABI/kernel телевизора.
2. Подготовить собственный локальный профиль, процесс клиента, проверки маршрутов/DNS и очистку только его ресурсов. Авторизацию между движками не переносить автоматически.
3. Проверить on/off, отсутствие ложного on, отказ клиента, восстановление сети и освобождение ресурсов. Общий controller проверяется mock-адаптером независимо от Tailscale.
4. Добавить локальный профиль в `profiles[providerId]`. `available` должен подтверждать установленные бинарники и готовность профиля, не раскрывая его. После отключения прежнего движка и quiescent=true выбрать новый в настройках Hearth. Команды `providers` и `select` возвращают только подготовленные реализации из реестра; активное подключение нельзя переключить. UI и control.js остаются прежними.

Xray и sing-box — возможные следующие адаптеры, **не реализованные клиенты этого проекта**. Их пока нельзя включить одной сменой имени в JSON: неизвестный provider отклоняется явно. После добавления и проверки нужного адаптера выбор действительно сводится к selector и локальному профилю, без переделки управляющего контура.
